## 问题陈述

中文小组需要能互相看见、听见，并通过标注参会者的字幕跟上讨论的浏览器会议工具。
识别服务故障不应打断交流。维护者同时需要一个展示 Rust RTC 服务端工程能力的求职项目，
用可复现证据体现协议、弱网和资源生命周期方面的工作。

## 方案

同一局域网内，三人使用独立设备上的电脑端 Chrome 参会。任何人可以创建、分享链接。
访客填写昵称、预览摄像头和麦克风，再主动加入；三人均可收发音视频。
会中显示中文字幕，允许修订临时结果，会议结束后清空。
空会议宽限期为连续 60 秒，过期后旧链接不能加入或重建该会议。

每周投入 10 小时，目标为 2027 年 3—4 月求职。识别开发测试每月预算 30 元人民币。
允许外部 ASR，但本规格没有完成服务商选择或付费开通。

## 用户故事

1. 作为会议创建者，我希望生成可分享链接，以便其他人加入。
2. 作为参会者，我希望成员权限相同，以便无需主持人也能开会。
3. 作为访客，我希望不注册账号即可填写昵称，以便便捷加入。
4. 作为访客，我希望入会前预览设备，以便确认设备可用。
5. 作为访客，我希望看到可操作的设备权限错误，以便解决问题。
6. 作为参会者，我希望看见并听见另外两人，以便共同讨论。
7. 作为访客，我希望看到明确的会议已满提示，以便理解无法加入的原因。
8. 作为参会者，我希望字幕标注正确的人，以便跟上讨论。
9. 作为参会者，我希望尽早看到可修订字幕，以便不必等待整句话结束。
10. 作为参会者，我希望确认后的文字固定，以便稳定阅读。
11. 作为参会者，我希望同时说话时字幕仍分属各人，以免互相覆盖。
12. 作为参会者，我希望识别失败时通话继续，以便继续讨论。
13. 作为参会者，我希望知道字幕不可用，以便意识到内容可能缺失。
14. 作为参会者，我希望识别恢复后只处理新语音，以免旧音频形成延迟积压。
15. 作为参会者，我希望空会议保留短暂宽限期，以免短暂离线立即结束会议。
16. 作为访客，我希望看到链接过期提示，以便获取新会议链接。
17. 作为参会者，我希望会后清空字幕，以免留下文字记录。
18. 作为开发者，我希望限制识别费用，以便在月度预算内测试。
19. 作为开发者，我希望重复运行浏览器及故障测试，以便验证改动。
20. 作为求职者，我希望用测量和解释展示个人改动，以便证明超出引入上游源码的工作。

## 需求与验收

编号描述预期行为，不代表交付状态。来自范围的要求已确认；底层协议、恢复和测量细节仍需验证。

| ID | 需求 | 可观察验收 |
|----|------|------------|
| REQ-001 | 人人可创建、分享会议，无主持人角色。 | 创建者与其他参会者权限相同。 |
| REQ-002 | 局域网电脑端 Chrome，昵称和设备预览后主动加入。 | 三台独立电脑可加入；预览不发布会议媒体；权限拒绝或连接失败时有可操作状态。 |
| REQ-003 | 服务端强制最多三人。 | 第四人及并发加入不能突破上限或打断已有通话。 |
| REQ-004 | 第一版包含麦克风与摄像头。 | 三人同时发布媒体并接收其余两人的音视频。 |
| REQ-005 | 正确归属的逐人中文字幕。 | 重叠发言时字幕独立归属，不通过识别文本猜测会议身份。 |
| REQ-006 | 临时结果可修订，最终字幕固定。 | 修订只更新对应片段，不静默重写最终文字，不修改其他人或旧连接的字幕。 |
| REQ-007 | 识别故障不影响通话。 | ASR 断连或超时显示字幕不可用，音视频继续可用。 |
| REQ-008 | 跳过故障期间语音。 | 不为事后转写保存故障期间音频；恢复后处理新语音，不回放旧结果积压。 |
| REQ-009 | 空会议宽限期为连续 60 秒。 | 过期前有效入会取消空房计时；连续为空达到 60 秒后结束。 |
| REQ-010 | 会议结束后旧链接失效并清空字幕。 | 旧链接不能重建房间；页面及服务端持有的字幕清空。 |
| REQ-011 | 会后不留存字幕。 | 产品、SFU 持久日志及浏览器存储无字幕正文；声称全链路满足前须核实供应商留存。 |
| REQ-012 | 识别开发测试每月最多 30 元。 | 计费调用前记录价格模型和保守用量限制；预算耗尽停止识别，通话继续。 |
| REQ-013 | 可复现工程证据。 | 多浏览器开发检查及三台电脑验收记录版本、条件、行为、资源和延迟测量。 |

## 实现决策

- 按 [ADR 0002](decisions/0002-rust-source-transition.zh.md)，自行维护的应用代码使用 Rust，包括浏览器界面、后端与 SFU。旧 RTCPilot 实现及 libuv/CMake 选型已退役；保留署名与历史证据。
- 浏览器媒体通过 WebRTC 与 SFU。Rust 媒体库、信令契约、进程布局和框架尚未选定。
- 语音运行时保持外置。声称已实现或启动计费调用前，验证仅识别模式、独立输入、留存、费用及替代接入。
- 昵称只作显示，不是授权凭据或唯一身份。可信所有者验证会议/参会者身份、准入与人数上限。
- 识别服从通话。有界队列与取消须避免慢识别阻塞媒体转发或保留故障期间音频；服务商凭据留在服务端。
- 会议结束是产品状态，与传输清理不同。旧事件不能复活已结束会议，也不能修改替代连接。

### 实现前待解决的细节

以下是设计问题，不代表新增产品决定或现有能力：

- 根据上游实际契约，定义字幕的参会者/连接身份、片段身份、修订、最终状态与顺序。
- 定义断线检测、重连名额归属、同名显示、首次加入前及重启后的链接失效、准入与空会议计时竞争；保留三人上限及连续空会议 60 秒语义。
- 验证音频格式、会话限制、服务商留存/计价与可实行的预算停止策略；本地计数不能单独保证服务商账单。
- 测量媒体/资源基线，区分首段字幕与最终字幕延迟，再设定数值目标。
- 仅在调查发现具体歧义时细化验收细节，并同步更新本文件及译文。

## 测试决策

通过真实信令与 WebRTC 到 Rust SFU 验证浏览器会议流程。测试与调用方使用相同接口，观察用户可见行为和媒体。本机多浏览器开发结果须与 PRD 的三台电脑验收分开。

用外部识别替身产生临时/最终、交错、延迟、过期和失败事件。真实解码及服务商行为须单独通过受限联调验证。覆盖准入、会议/参会者生命周期、字幕展示、取消和故障隔离；到期竞争使用可控时钟或等价确定性驱动。

已删除的 C++ 测试及历史报告仅作参考证据。当前根测试验证文档规则；Rust 构建、单元/接口测试及运行验证仍须建立。分别记录识别替身、真实服务商、合成浏览器及实体设备结果。弱网测量须记录注入的丢包/延迟条件，并在等价条件下比较。

## 非目标

账号、主持人控制、录音回放、保存纪要、翻译、AI 语音回复、屏幕共享、超过三人、公网或移动端验收、嵌入语音运行时仍不在首个版本范围内。

Rust SFU 属于已确认的技术方向。依赖选型与实现范围须单独形成可审阅工作项；本次文档整理不启动实现，也不关闭运行 gate。
