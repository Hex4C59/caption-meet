## 目标

做一个中文小组会议项目，展示 C++ RTC 服务端的媒体转发、协议、弱网处理和稳定性能力。
计划在 2027 年 3—4 月投递岗位，当前具备 C++ 和音视频基础，每周投入 10 小时。

## 已确定范围

| 项目 | 要求 |
|------|------|
| 人数 | 最多 3 人；第 4 人看到会议已满，不影响已入会成员。 |
| 客户端与网络 | 电脑端 Chrome，每人独立设备，同一局域网。 |
| 媒体 | 第一版就支持 3 人同时使用麦克风和摄像头。 |
| 创建 | 任何人都能创建会议并分享链接，不设主持人及其专属权限。 |
| 加入 | 打开链接、填写昵称、预览摄像头和麦克风，再主动加入。 |
| 字幕 | 会中显示带参会者标识的中文字幕；临时结果可修订，确认后的结果固定。 |
| 留存 | 会后不保存字幕，结束会议时清空；实现及选型须处理已有正文日志并核实供应商留存。 |
| 识别 | 允许外部语音识别 API，尚未选定服务商。 |
| 识别预算 | 开发测试每月最多 30 元人民币。 |
| 识别故障 | 提示字幕不可用，音视频继续；故障期间的语音跳过，不缓存补转写，恢复后处理新语音。 |
| 结束 | 无人在线持续 60 秒后结束会议、清空字幕，旧链接不能再加入。 |
| 验证 | 开发阶段用多个浏览器实例；最终可安排 3 台真实电脑验收。 |

录音回放、翻译、AI 语音回复、屏幕共享、账号系统、公网或移动端支持、更大规模会议，
均不在本次已确定范围内。这是在描述范围边界，不代表逐项询问后否决过这些功能。

## 待写入规格的可观察验收

1. 局域网内 3 台电脑经过预览流程加入，彼此收发音视频；第 4 人被拒绝加入。
2. 多人同时说话时字幕归属正确，修订更新对应的临时片段，不覆盖别人的字幕。
3. 识别故障时有可见提示，通话继续；恢复后不补转写故障期间的语音。
4. 空会议在 60 秒宽限期内仍可加入；如果持续为空达到 60 秒，结束并清空字幕，拒绝旧链接。
5. 退出、重入和迟到的识别结果不会复活已结束会议、把旧字幕贴到新参会者身上，或造成资源无限积压。
6. 应用及 SFU 持久日志不包含字幕正文；声称全链路不留存前须核实服务商规则。
7. 在注明条件的实验中测量延迟、丢包、CPU、内存及资源回收；取得第一份基线后制定数值门槛。

第 5—7 项是将目标转成工程验收的建议，不是已测得的结果。重连期间的名额归属、同名显示、
断线判定和延迟口径还需要在规格中明确。

## 建议交付顺序

1. 复现仓库内 SFU 构建和浏览器音视频通话，记录依赖、协议行为及首份测量基线。
2. 完成 3 人局域网会议，包括加入、人数限制、成员清理、会议结束和旧链接拒绝。
3. 接入逐人实时识别、临时及最终字幕、故障隔离、不留存与预算控制方案。
4. 验证弱网、断线重入和重复创建退出，整理可复现测量、回归测试及三台电脑演示。

基线建立前不承诺具体完成日期。个人改动、定位过程及优化前后测量，要与上游已有能力分开记录。

## 仍需完成的技术工作

- 用实际客户端验证 3 路媒体及识别并发。
- 验证临时及最终事件、音频格式转换；不能假设 RTP/Opus 可以直接送入识别 API。
- 根据官方价格、并发、开通条件和留存规则选择识别服务。30 元是预算约束，
  不代表本地计数器已经能精确限制供应商账单。
- 明确局域网浏览器安全访问、会议身份与链接校验、重连、有限队列、取消及资源清理责任。
- 编写规格时调整旧陪练 PRD 和单人/AI 架构假设，保留 RTCPilot 仓库内维护决策及密钥保护规则。
- 现行规则要求 VoiceAgent 保持外部服务。先调查其纯识别适配能力，不能擅自绕过它或重写 AI 运行时；
  如确需调整集成策略，应形成具体决策供审阅。
